# 剧星设计语言系统

剧星 - Apple 风格下的品牌化业务平台设计语言

---

## 1. 目标与适用场景

### 1.1 目标
- 建立可复用、可维护、可落地的品牌化业务平台设计系统。
- 同时服务两类核心场景：
  - 场景 A：内容页（内容工作台）
  - 场景 B：业务工作台
- 以 Token 统一视觉基础，以组件语言统一交互行为，以模板语言统一页面结构。

### 1.2 适用范围
- Web 原型、运营工作台、内容平台页面、AIGC 对话式工作台页面、数据工作台页面。
- 前端技术栈不限（原生 HTML/CSS/JS、Vue、React 等）。

### 1.3 基础共识
- 用户可见内容保持中文表达。
- 页面展示、日志提示、接口返回中避免使用表情符号。
- HTTP 状态码默认返回 `200`，业务状态通过响应体 `code` 字段表达。
- 后端接口参数优先走参数体/查询参数，避免通过路由路径传参。

## 2. 设计语言（保留方向，升级表达）

### 2.1 视觉原则
- 风格关键词统一为：克制、编辑化、内容优先、轻科技、品牌感、杂志感。
- 页面不追求传统系统后台气质，而是更像 Apple 内容系统的企业工作台。
- 视觉表达强调“内容平台 + 创意平台 + 数据平台”的融合感。

### 2.2 体验原则
- 交互反馈保持清晰、节制、可预期。
- 推荐以“可扫描性”和“高频路径效率”组织界面。
- 信息展示优先级高于控件密度。
- 内容优先于操作，操作优先于装饰。
- 页面优先传递重点信息，再承载操作行为，保持“扫一眼知道重点”。

### 2.3 品牌表达原则
- 页面建议体现剧星“内容 + 数据 + 创意 + 技术”的品牌气质。
- 视觉表达优先避免传统企业后台的生硬与工具感。
- 页面更接近“品牌工作台”，而非“管理系统”。
- 在效率与表达并行时，优先保持内容质感与品牌统一性。
- 统一认知：剧星不是工具系统，而是品牌化业务平台。

### 2.4 剧星视觉识别原则
- 剧星界面应具备可识别的“内容科技感”。
- 品牌识别不依赖 Logo，更依赖统一的留白、节奏、色彩与信息结构。
- 页面应具备“内容感 + 数据感 + 轻科技感”的统一气质。
- 所有页面保持剧星统一视觉语境，避免随业务模块各自生长。

### 2.5 品牌节奏原则
- 页面通过留白、字号、块级密度建立节奏，而非依赖分割线切块。
- 强信息放大，弱信息后退，形成稳定阅读流。
- 建议采用“标题 -> 重点 -> 补充 -> 操作”的固定阅读节奏。
- 页面优先建立阅读秩序，再承载交互行为。

### 2.6 平台表达原则
- 页面不追求功能堆叠，而追求重点清晰。
- 功能不以数量体现价值，而以信息组织体现效率。
- 页面优先让用户理解当前重点，再决定下一步动作。
- 每个页面都应具备明确主线，而不是功能并列堆积。

### 2.7 无障碍原则（WCAG 2.1 AA）
- 根节点设置 `lang="zh-CN"`。
- 可交互元素支持键盘聚焦与操作。
- 焦点样式保持可见，避免直接移除焦点表现。
- 文本与背景对比度建议满足 AA 标准（正文至少 4.5:1）。

## 3. Information Hierarchy（信息层级）

### 3.1 四级信息层级模型
- **Level 1：核心信息**（页面标题 / 核心数据 / 当前重点）
- **Level 2：主要内容**（内容主体 / 趋势 / 主任务）
- **Level 3：辅助信息**（说明 / 标签 / 次级状态）
- **Level 4：弱信息**（时间 / 注释 / 补充说明）

### 3.2 使用建议
- 页面优先定义信息层级，再摆放组件。
- 避免所有内容同权展示。
- 每个页面都建议具备明确视觉主次。

## 4. Design Token 体系

> 以下 Token 是设计与前端主要对齐源（Single Source of Truth）。页面与组件优先消费 Token，尽量避免定义近似值。

### 4.1 颜色 Token（Color）

#### 4.1.1 品牌与语义色
- `--color-brand-500`: `#007AFF`
- `--color-brand-600`: `#0051D5`（悬浮/按下）
- `--color-brand-nav-active`: `#0052D9`
- `--color-brand-accent-purple`: `#6E5BFF`
- `--color-brand-accent-cyan`: `#4C9AFF`
- `--color-success-500`: `#00A870`
- `--color-warning-500`: `#D93A00`

#### 4.1.2 品牌辅助色使用建议
- 主交互默认使用 iOS Blue（`--color-brand-500`）。
- 紫色优先用于品牌强调、内容标签、数据高亮。
- 青色优先用于图表辅助与科技感点缀。
- 紫色与青色建议不替代主按钮主色。
- 品牌辅助色避免大面积铺色，优先局部强化识别。

#### 4.1.3 中性色与文字
- `--color-bg-page`: `#F2F2F7`
- `--color-bg-surface`: `#FFFFFF`
- `--color-bg-subtle`: `#F5F5F7`
- `--color-fill-100`: `#E5E5EA`
- `--color-text-primary`: `#1D1D1F`
- `--color-text-regular`: `rgba(60, 60, 67, 0.85)`
- `--color-text-secondary`: `rgba(60, 60, 67, 0.6)`
- `--color-text-weak`: `#6E6E73`
- `--color-border-default`: `rgba(60, 60, 67, 0.12)`
- `--color-border-light`: `rgba(60, 60, 67, 0.08)`

### 4.2 字体 Token（Typography）

- `--font-family-sans`:
  `-apple-system, BlinkMacSystemFont, "SF Pro Text", "SF Pro Display", "Helvetica Neue", "PingFang SC", sans-serif`

#### 4.2.1 语义字号映射

- 卡片标题：`17px / 600`
- 正文：`14px / 400~500`
- 辅助信息：`12px~13px / 400~500`

### 4.3 尺寸 Token（Radius / Spacing / Layout）

#### 4.3.1 圆角
- `--radius-6`: `6px`
- `--radius-8`: `8px`
- `--radius-10`: `10px`
- `--radius-12`: `12px`
- `--radius-24`: `24px`

#### 4.3.2 间距
- `--space-4`: `4px`
- `--space-8`: `8px`
- `--space-12`: `12px`
- `--space-16`: `16px`
- `--space-20`: `20px`
- `--space-24`: `24px`

#### 4.3.3 布局尺寸
- `--layout-sidebar-width`: `220px`
- `--layout-sidebar-width-collapsed`: `54px`
- `--layout-topbar-height`: `60px`
- `--layout-breakpoint-mobile`: `992px`

### 4.4 层级 Token（Elevation / Z-index）

#### 4.4.1 阴影
- `--shadow-light`: `0 1px 3px rgba(0, 0, 0, 0.06)`
- `--shadow-default`: `0 2px 8px rgba(0, 0, 0, 0.08)`
- `--shadow-modal`: `0 12px 48px rgba(0, 0, 0, 0.15)`

#### 4.4.2 层级
- `--z-base`: `1`
- `--z-sticky`: `100`
- `--z-dropdown`: `1000`
- `--z-modal`: `2000`
- `--z-toast`: `3000`

### 4.5 动效 Token（Motion）

#### 4.5.1 时长
- `--motion-duration-fast`: `120ms`
- `--motion-duration-normal`: `200ms`
- `--motion-duration-slow`: `280ms`

#### 4.5.2 缓动函数
- `--motion-ease-standard`: `cubic-bezier(0.2, 0, 0, 1)`
- `--motion-ease-emphasized`: `cubic-bezier(0.2, 0, 0, 1.2)`
- `--motion-ease-exit`: `cubic-bezier(0.4, 0, 1, 1)`

#### 4.5.3 使用建议
- Hover/Focus 反馈推荐使用 `120ms`。
- 面板切换、分段控制切换推荐使用 `200ms`。
- 弹层进入/退出推荐使用 `200ms~280ms`，保持自然过渡。

## 5. 组件语言（含状态矩阵）

### 5.1 按钮 Button

#### 5.1.1 类型
- 主按钮（Primary）：品牌蓝底，白字。
- 次按钮（Default）：白底、蓝边、蓝字。
- 文字按钮（Text）：无填充，用于次级操作。

#### 5.1.2 状态
- Default：可点击，边界清晰。
- Hover：颜色加深或背景轻微变浅。
- Active：进一步强调按下态（使用 `--color-brand-600`）。
- Disabled：降低不透明度并弱化交互感。
- Focus-visible：保持高对比焦点描边。

### 5.2 输入 Input / Select / Textarea

- 圆角 `10px`，边框 `0.5px/1px`。
- Hover：边框加深一级。
- Focus：主色描边（`1px` 外描边或同等可见表现）。
- Error/Warning：使用低饱和语义色边框与说明文案。
- Readonly/Disabled：优先保证可读性。

### 5.3 分段控制 Segmented Control

- 容器：浅灰背景 + `4px` 内边距 + `10px` 圆角。
- 选项：`6px` 圆角；激活项白底 + 轻阴影。
- 状态：默认、悬浮、激活、禁用、焦点。

### 5.4 卡片 Card（编辑卡片 / 内容卡片优先）

- 卡片优先采用“大留白 + 弱边界 + 强内容层级”。
- 减少纯功能框感，增强内容块感与杂志化节奏。
- 卡片更像编辑模块，而非信息盒子。
- 建议减少描边与分割线堆叠。
- 推荐通过标题、留白、配图建立层级，而不是依赖边框切块。
- **卡片的本质是承载“内容层级”，不是承载“模块边界”。**
- 圆角默认 `12px`（主视觉内容卡可提升到 `24px`）。

### 5.5 表格 Table（内容列表化优先）

- 默认更像“内容列表”而不是“数据库表”。
- 弱化强网格线，优先使用留白、字重、分组区分层级。
- 减少横纵硬分割，避免传统表格压迫感。
- 推荐 Card List 作为默认替代模式。
- 数据密集场景再切换标准 Table。

### 5.6 状态胶囊 Status Pill

- 小尺寸、低饱和、短文本。
- 建议映射：
  - 成功：绿系浅底 + 深绿文字
  - 警告：橙系浅底 + 深橙文字
  - 处理中：蓝灰系浅底 + 深蓝灰文字

### 5.7 导航组件（Sidebar / Topbar / User Menu）

#### 5.7.1 左侧菜单
- 默认：透明或侧栏底色。
- Hover：`#E8E8ED`。
- Active：`#0052D9` + 白字。
- 单页面建议仅存在一个激活主项。

#### 5.7.2 顶栏
- 高度固定 `60px`。
- 左：平台标识；中：上下文；右：全局操作与协同入口。

#### 5.7.3 用户区
- 结构推荐：头像圆点 + 用户名 + 下拉箭头。
- 悬浮或聚焦时显示浅底高亮，焦点保持可见。

## 6. 交互语言（Interaction Spec）

### 6.1 导航与路由同步
- 导航激活态优先由当前 URL/路由计算。
- 支持刷新、前进、后退后的状态恢复。
- 路由未匹配时可不高亮或高亮首页，避免错误高亮。

### 6.2 反馈与提示
- 即时反馈：点击、切换、提交提供即时视觉反馈。
- 异步反馈：生成中、排队中、已完成保持稳定状态表达。
- 错误反馈：说明原因并提供清晰下一步。

### 6.3 状态流转（建议）
- `待提交` -> `提交中` -> `处理中` -> `成功/失败`
- 失败建议支持重试，并保留上下文输入。

### 6.4 键盘与可访问性行为
- `Tab` 顺序遵循视觉阅读路径。
- 可操作控件支持键盘触发（Enter/Space）。
- 下拉菜单、弹层可通过 Esc 关闭（如有弹层）。

### 6.5 Empty State（品牌化空状态）
- 空状态优先传达“下一步做什么”，而不是“当前没有数据”。
- 建议使用“简短标题 + 一句说明 + 单一明确动作”。
- 避免空白占位与机械式提示。
- 空状态同样是品牌表达的一部分。

## 7. 页面模板语言（可直接用于原型生成）

### 全局页面表达建议
- 页面优先呈现信息，其次承载输入。
- 表单仅在必要时出现，不应主导页面视觉。
- 输入是动作，不是页面主体。

### 7.1 模板 A：内容工作台
- 骨架：顶部导航 -> 大标题 -> 主打沉浸卡 -> 内容列表
- 特征：大留白、大圆角、强标题、弱控件干扰
- 适用：内容推荐、活动专题、品牌内容运营

### 7.2 模板 B：业务工作台
- 骨架：侧边导航 + 顶栏 + 内容网格 + 操作面板
- 特征：业务协同可达、状态可见、信息结构清晰
- 适用：广告运营、内容编排、任务协同、数据监控

### 7.3 模板 C：AIGC 对话式创作工作台
- 骨架：会话列表 + 对话流 + 参数面板 + 输入区
- 特征：创作流程连贯、结果可回溯、参数可控
- 适用：图片生成、视频生成、文生图/图生视频混合流程

### 7.4 业务驾驶舱不是 BI（品牌化业务驾驶舱原则）
- 业务驾驶舱不追求传统 BI 的复杂分析台结构。
- 推荐突出实时感、变化感、趋势感、重点感。
- 适合客户可见、领导可扫读、业务可快速判断。
- 默认以“重点指标 + 趋势 + 异常提醒”组织，而非“多维透视报表”。

## 8. Data Visualization（数据可视化规范）

### 8.1 图表风格基调
- 遵循 Apple 式极简图表风格。
- 默认弱边界、弱网格、低饱和。
- 优先展示趋势、比例、变化，不强调复杂坐标系统。
- 优先传达趋势/排名/占比，避免堆叠数字。
- 图表服务“扫读”与“判断”，不追求复杂分析台体验。
- 图表首先服务表达，其次服务分析。
- 默认用于传达判断，不用于承载复杂推演。

### 8.2 图表配色映射
- 主趋势：iOS Blue（`--color-brand-500`）
- 强调趋势：Brand Purple（`--color-brand-accent-purple`）
- 辅助趋势：Cyan（`--color-brand-accent-cyan`）/ Gray（中性色）
- 风险：Orange（`--color-warning-500`）
- 成功：Green（`--color-success-500`）

### 8.3 图表使用建议
- 同一图中主色建议不超过 1 个，强调色建议不超过 1 个。
- 默认隐藏重网格线，可保留关键基准线。
- 轴标签与数据标签保持“够用即可”，避免视觉噪音。
- 数据密集图建议提供分组切换或筛选，减少一次性堆叠维度。

### 8.4 推荐图表优先级
1. 趋势：折线图 / 面积图（简化版）
2. 占比：环图 / 条形占比图
3. 排名：横向条形图
4. 实时状态：指标卡 + 微趋势（sparkline）

## 9. 落地方式

### 9.1 设计侧流程
1. 先确定页面模板（A/B/C）。
2. 再确定信息层级与组件状态。
3. 最后填充业务内容与文案。

### 9.2 前端侧流程
1. 初始化 Token 文件并注入 `:root`。
2. 按组件语言实现基础组件库。
3. 按页面模板语言拼装业务页面。
4. 对照交互语言补全状态流转与反馈。

### 9.3 验收清单
- 是否优先使用 Token，减少风格漂移值。
- 是否覆盖组件关键状态。
- 是否满足中文文案与无障碍体验。
- 是否保持路由同步与接口返回约定。
- 是否体现“品牌工作台”而非传统后台语气。

### 9.4 最终执行清单
1. 保持 Apple + 剧星视觉方向。
2. Token 先行，组件次之，页面最后实现。
3. 默认优先内容表达，再承载业务操作。
4. 数据呈现优先趋势与重点，不做传统 BI 堆叠。
5. 全链路中文文案，避免表情符号。
6. 剧星默认不是工具系统，而是可持续演进的品牌产品。
