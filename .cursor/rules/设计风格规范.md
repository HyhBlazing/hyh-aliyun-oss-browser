# 剧星管理系统 - 设计风格规范

## 1. 设计原则

| 原则   | 说明                             |
| ------ | -------------------------------- |
| 风格   | Apple/iOS 风格                   |
| 色彩   | 素色设计，低饱和度，禁止高饱和色 |
| 无障碍 | 支持 WCAG 2.1 AA 级别            |
| 语言   | 用户可见内容统一中文             |

## 6. 组件风格

### 6.1 按钮

- **主按钮**：背景/边框 `#007AFF`，悬浮 `#0051d5`
- **默认按钮**：白底蓝边蓝字，悬浮浅蓝背景
- 焦点需保留可见轮廓，以满足 WCAG 2.1 AA（避免 `outline: none`）

### 6.2 输入框

- 圆角 10px
- 边框 `0.5px`，悬浮略深，聚焦主色 1px
- 禁用、只读态需保持足够对比度

### 6.3 单选框 / 复选框

- 选中态：背景和边框使用主色 `#007AFF`

### 6.4 标签页（分段控制）

- 整体背景 `var(--el-fill-color)`，内边距 4px，圆角 10px
- 选项圆角 6px，激活项白底 + 轻阴影
- 隐藏下划线/指示条，用背景区分激活态

### 6.5 表格

- 表头背景 `var(--el-fill-color-light)`
- 边框 `0.5px solid var(--el-border-color)`
- 斑马纹使用 `var(--el-fill-color-light)`
- 表头文字次要色、字重 500

### 6.6 卡片

- 圆角 12px
- 边框 `0.5px solid var(--el-border-color)`
- 阴影 `var(--el-box-shadow-light)`
- 标题 16px 20px，字重 600

### 6.7 侧边栏菜单

- 背景 `#f5f5f7`
- 项内边距 12px 16px，圆角 10px
- 悬浮 `#e8e8ed`
- 激活 `#0052d9` 背景，白字

## 7. 无障碍（WCAG 2.1 AA）

### 7.1 已落实

- `lang="zh-CN"`
- `role="navigation"`、`aria-label="主导航"`、`role="menuitem"`
- 合理的 `viewport` 与基础语义结构
- Element Plus 自带的焦点管理与 `aria-*` 属性

### 7.2 需注意

- **禁止** 对 `:focus` / `:focus-visible` 使用 `outline: none`，应保留或替换为符合对比度要求的焦点样式
- 色彩对比度至少 4.5:1（正文）、3:1（大文字/图标）
- 交互元素支持键盘操作和清晰的焦点指示

## 9. 接口与提示规范

- HTTP 状态码统一返回 200，业务状态由响应体 `code` 字段表示
- 接口 `message`、页面提示、注释说明均为中文
- 禁止在接口返回、页面展示、日志提示中使用表情符号

## 11. 导航设计与交互逻辑

### 11.1 左侧菜单（侧边栏）设计逻辑

- **信息架构**：左侧菜单承载系统主要功能模块（如「消耗概览」「报表」「素材评估」「筹备资金」等），按照「高频运营功能在上、配置与管理在下」的顺序排列。
- **结构形式**：容器采用固定宽度侧栏（约 220px），内容区域自适应；菜单由脚本注入，外层使用 `nav` 元素并设置 `role="navigation"` 和 `aria-label="主导航"`，单项使用 `<a>` 标签并设置 `role="menuitem"`。
- **视觉状态**：
  - 默认：背景透明或与侧栏背景一致，文字使用菜单未激活色。
  - 悬浮：背景使用浅灰 `#e8e8ed`，不改变文字颜色，体现可点击性。
  - 激活：背景使用主导航激活色 `#0052d9`，文字为白色，仅允许单一菜单项处于激活状态。
- **选中逻辑**：
  - 静态页面：通过初始化参数 `activeKey` 或根据当前页面 URL 计算激活项。
  - SPA 场景：根据当前路由路径匹配菜单项 `key` 或 `path`，路由变化时同步更新激活状态。
  - 任何情况下，视觉激活状态必须与当前实际页面/路由保持一致，禁止出现「样式高亮但内容非当前页」的情况。
- **交互逻辑**：
  - 点击菜单项后，进行路由跳转或页面跳转，不做破坏性操作（如删除、停用等）。
  - 预留 `hasDropdown` 等配置用于未来二级菜单或折叠菜单扩展，当前版本以一级菜单为主。
  - 支持通过配置项扩展菜单列表，业务项目只需维护菜单配置而不修改组件逻辑。
- **可访问性与键盘支持**：
  - 菜单项需可通过 `Tab` 键逐项聚焦，并在聚焦时出现清晰的焦点样式（轮廓或背景变化），避免使用 `outline: none` 直接移除。
  - 激活状态与焦点状态在视觉上区分开（如激活为蓝底白字，焦点为额外的描边或阴影）。

### 11.2 顶部菜单（顶栏）设计逻辑

- **角色定位**：
  - 顶部菜单（顶栏）负责系统级导航与上下文信息展示，如系统标题、当前工作空间、全局搜索、用户信息、全局入口（通知、设置等）。
  - 在支持多布局的 SPA 中，顶部菜单结合不同布局形态（左侧布局、顶部布局、混合布局）承担不同层级的导航职能：
    - 左侧布局：顶部以系统信息与全局操作为主，一级导航主要在左侧菜单。
    - 顶部布局：顶部承载一级导航标签，左侧可弱化或隐藏。
    - 混合布局：顶部展示一级模块切换，左侧展示当前模块下的二级菜单。
- **导航逻辑**：
  - 顶部一级菜单点击后，切换当前业务域/模块，同时刷新左侧菜单内容，使之只展示当前模块下的功能。
  - 顶部菜单的激活态与路由信息保持同步（例如根据路由前缀匹配所属模块）。
  - 对于带标签页（多页签）的场景，顶部导航只负责模块切换，具体页面的打开/关闭由标签页组件管理，保持职责清晰。
- **交互规范**：
  - 顶栏左侧固定展示系统名称/Logo，点击可回到系统默认首页。
  - 顶栏右侧统一放置用户头像、下拉菜单（退出登录、个人中心等）、全局设置入口与其他全局操作。
  - 顶部菜单与左侧菜单均不得在点击后直接触发不可逆操作，所有破坏性操作必须通过明确的按钮或菜单项并配合确认交互。
- **响应式与兼容性**：
  - 在宽度接近断点（约 992px）时，可将部分文字导航收缩为图标或折叠菜单（如汉堡按钮），确保不出现文字溢出与折行。
  - 移动端可将顶部菜单简化为单行图标导航，左侧菜单折叠为抽屉式导航，由顶部入口控制打开/关闭。

### 11.3 导航与路由同步规则

- **单一真相来源**：左侧菜单、顶部菜单、标签页等所有导航组件的激活状态必须由当前路由或 URL 统一驱动，而不是各自维护独立状态。
- **刷新保持状态**：页面刷新后，仍然根据当前路由/URL 恢复正确的激活菜单与展开状态，避免刷新后高亮丢失或错误。
- **浏览器导航兼容**：前进/后退操作应正确更新左侧、顶部菜单与标签页的激活状态，保证导航与浏览器历史行为一致。
- **错误防护**：当路由未在菜单中找到匹配项时，可选用默认高亮（如首页）或不高亮任何菜单，但不得高亮错误的菜单项。

### 11.4 本项目统一实现规范（必须遵守）

- **统一渲染入口**：
  - 顶部菜单与左侧菜单统一由 `js/menu.js` 渲染，不允许在各业务页面重复编写完整导航结构。
  - 页面仅保留导航占位容器：
    - 顶部：`<header id="global-header" class="navbar" role="banner"></header>`
    - 左侧：`<nav id="sidebar-nav" role="navigation" aria-label="主导航"></nav>`
- **初始化机制**：
  - `menu.js` 在页面加载后自动检测 `#global-header` 与 `#sidebar-nav`，存在则注入对应导航 DOM。
  - 顶部与左侧导航都允许通过函数参数扩展，但默认无需页面写额外逻辑。
- **激活项来源**：
  - 优先读取 `body[data-menu-active]`。
  - 若未显式指定，则根据当前 URL 自动匹配菜单配置并计算激活项。
  - 菜单配置统一维护在 `js/menu-config.js`，业务页面不得硬编码菜单项。
- **路径与资源规则**：
  - Logo 与导航资源路径由脚本按项目根路径计算，避免不同目录层级下相对路径失效。
  - 用户姓名等动态文本在注入前需进行 HTML 转义，避免渲染注入风险。

### 11.5 顶栏右上角用户区交互规范（默认态/悬浮态）

- **结构组成**：右上角统一由「头像圆点 + 用户姓名 + 下拉箭头 + 退出菜单」组成，禁止页面自定义替换为其他结构。
- **默认态**：
  - 容器为胶囊形，背景透明；
  - 头像为 24x24 圆形，低饱和灰蓝底，白色文字；
  - 姓名字体 15px，颜色使用主文字色；
  - 箭头朝下，颜色使用次要文字色。
- **悬浮/聚焦态**：
  - 鼠标悬浮或键盘聚焦（`focus-within`）时，容器背景切换为浅填充色；
  - 下拉箭头旋转 180 度；
  - 下拉菜单显示，内容仅展示中文动作项（当前为“退出”）。
- **退出菜单样式**：
  - 菜单采用白底、浅边框、轻阴影，圆角与系统组件保持一致；
  - “退出”文本使用低饱和红色强调，悬浮时仅改变浅背景，不使用高饱和警示色。
- **无障碍要求**：
  - 用户区容器必须可键盘聚焦（如 `tabindex="0"`）；
  - 保留可见焦点描边，禁止移除焦点样式；
  - 下拉菜单项保留 `role="menuitem"` 并可通过键盘访问。
